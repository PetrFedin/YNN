# Выводы по оптимизации бизнеса — только из имеющихся данных

Updated: 2026-07-27  
Статус: **management conclusions** · новых документов нет · **не** audited P&L · **не** SoT  

Вопрос: *сможем ли оптимизировать, работая с тем что есть?*  
**Ответ: да — по процессам, governance, кассовой дисциплине и приоритетам каналов; нет — по «P&L-эффекту в ₽ на всю компанию» без допущений.**

## 0. Рамка уверенности

| Уровень | Значение | Можно ли в совет/решения |
|---------|----------|---------------------------|
| **H — высокая** | Держится на сверках / структуре / принятых флагах | Да, как действие |
| **M — средняя** | Направление верное, величина эффекта неизвестна | Да, как гипотеза / пилот |
| **L — низкая** | Легко ошибиться из‑за дыр модели | Только как вопрос, не как приказ |

**Жёсткий запрет:** использовать goods operating **−58% (30 мес) / −74% (2025)** как доказательство «бизнес убыточен» или базу для сокращений. В базе нет ~МД-выручки (2025 DDS ≈ **232.6M ₽** @EUR100 при goods **72.9M ₽**).

## 1. Что бизнес собой представляет (из данных)

1. **Ядро — услуги МД / инд. пошив** (бриф ~83%; в нашей income-сверке 2025 МД доминирует над товаром).  
2. **Товар** — второй контур: TSUM тянет **~63%** costed goods revenue, IM ~29%, B2B ~7%.  
3. **Себестоимость в 1С по производству не ведётся** → экономика товара из Excel/W3; экономика МД по заказу **отсутствует**.  
4. **Комиссия ЦУМ**, по брифу, сидит в себестоимости УНФ → reported GM TSUM **37.9%** vs product **87.9%**. Резать ЦУМ «из‑за 37.9%» **опасно (L)**, пока нет ответа Меркушиной.  
5. **Декор с 2026** без деятельности → не operating; люди ушли в ИП.

## 2. Выводы H — делать сейчас (без новых файлов)

### H1. Разделить управленческую отчётность на два контура
**Зачем:** иначе решения по FTE/каналам принимаются на артефакте goods-bridge.  
**Действие:** любой отчёт помечает A (МД) / B (товар). Запрет слайда «operating −74% = YANINA».  
**Owner:** Янина / Сливяк.  
**Эффект:** качество решений ↑; прямой ₽ не считаем.

### H2. Зафиксировать политику ЦУМ (выбор C1/C2/C3) даже без договора — временно
Пока нет письма Меркушиной: **обязательный dual view** в каждом TSUM-отчёте.  
**Нельзя:** оптимизировать ассортимент ЦУМ по reported 37.9%.  
**Можно:** смотреть product GM ~87.9% + cash net-rate ~0.47 как *операционные* сигналы.  
**Owner:** Мокеева / Коптева.

### H3. Кассовая дисциплина = ближайшая «оптимизация денег»
Не стратегия продукта, а сбор уже заработанного / сверка:

| Рычаг | Факт | Действие |
|-------|------|----------|
| B2B open | **15 шт / 2.51M ₽** | Коптева: статус по каждой РН (платёж / взаимозачёт / нет) |
| IM OPEN | **6 месяцев**, coverage 80% | Сливяк: эквайринг-реестры или memo «почему gap» |
| MD DDS_LAG | **2026-06** | Дописать SALES DDS (если файла нет — зафиксировать process SLA) |
| BANK_DDS BLOCKED | не из‑за Salon (forensic 510/510) | Memo по статьям core, не перезаливка банка |

**Эффект H:** снижение неопределённости cash; потенциально до **~2.5M ₽** только по B2B open (если деньги существуют).

### H4. Не раздувать LE Декор в operating 2026+
Тег wind-down в отчётах/банковских классификациях.  
**Эффект:** меньше шума в сверках и налогах; подготовка к ликвидации без ложных KPI.

### H5. Остановить «оптимизацию» по quarantine / accepted loss без политики
- 0-3243 — не релинковать.  
- Wholesale OK loss (0-2493A/2496/2497) — **не повторять** без явного прайса (иначе это не стратегия, а утечка).  
**Owner:** Коптева / Коновалова.

### H6. Data operating model уже почти готова — внедрять, не копать файлы
RACI, gate, Owner Briefing, memo — это и есть первая волна трансформации:  
**еженедельный data ops** вместо разовых Excel-сборок.

## 3. Выводы M — направления оптимизации бизнеса (гипотезы)

### M1. Приоритет развития: МД-процесс, не «ещё больше товара вслепую»
МД даёт основной доход; unit-econ нет → оптимизация = **процесс**:
- предоплата / этапы оплаты (уже частично в МД workbook);
- SLA на внесение в SALES DDS (убери лаги как 2026-06);
- цикл примерки → оплата (бриф: примерки не в 1С — не блокировать SoT, но вести минимум в МД-книге);
- подряд/аутсорс vs свой цех — **качественно** (бриф: тираж мал для фабрик), без FTE-цифры.

**Пилот без новых IT:** 10–20 заказов — время/материалы/подряд из имеющихся колонок МД + DDS статьи; получить *первый* proxy contribution.

### M2. Внутри товара: IM выглядит здоровее reported-TSUM; B2B мал
| Канал | Rev (costed peri) | GM reported |
|-------|------------------:|------------:|
| IM | 56.7M | **81.8%** |
| B2B | 13.9M | **68.3%** |
| TSUM | 122.8M | **37.9%** (product **87.9%**) |

**Гипотеза M:** наращивать **IM** (свой канал, высокая GM, но cash-дыры чинить).  
**TSUM:** не резать по 37.9%; сначала C-режим. Если подтвердится product ~88% — ЦУМ **держать/растить** как объём при контроле комиссии.  
**B2B wholesale:** нишевый; не главный рычаг роста; закрыть 2.51M open.

### M3. Payroll — главный вес opex в goods-bridge (но это opex всей группы)
На 30 мес: payroll **~79.6M** при goods GM **102.4M**; rent ~23.9M.  
2025 vs 2024 (goods-peri): payroll **19.6M → 37.8M** при goods revenue **87.4 → 72.9M**.

**Интерпретация M (не приговор):** нагрузка ФОТ на *товарную* базу выросла — частично из‑за того, что ФОТ обслуживает и МД.  
**Оптимизация:** не «резать ЗП на 20%», а:
- разделить FTE/ФОТ proxy на МД vs товар vs shared (хотя бы экспертно Мокеева/Сливяк);
- смотреть выработку цеха/конструкторов на МД-заказы (качественно из брифа).

### M4. Аренда ~24M / 30 мес — второй рычаг после ФОТ
Салон сдаёт площади ИП (бриф).  
**Гипотеза:** проверить загрузку площадей vs МД/примерки (не из цифр склада — их нет). Решение — операционное, не из COGS.

### M5. Закупки / фурнитура
Фурнитура не в 1С (accepted constraint) → потери и остатки невидимы.  
**Оптимизация M:** минимальный Excel-регистр фурнитуры у Дендериной (приход/списание на заказ) — дешёвый контроль без 1С.

## 4. Выводы L — чего НЕ утверждать

| Утверждение | Почему нельзя |
|-------------|---------------|
| «Компания убыточна −58/−74%» | Нет МД в базе bridge |
| «Надо закрыть ЦУМ — маржа 38%» | Скорее артефакт комиссии в COGS |
| «Надо сократить N человек» | Нет person-level полноты + shared ФОТ |
| «Оптимальная доля каналов = …» | Нет contribution МД после прямых затрат |
| «Сэкономим X млн от Phase C» | Phase C ещё не посчитан |
