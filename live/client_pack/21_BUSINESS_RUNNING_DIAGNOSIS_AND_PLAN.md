## 0. Тезис (развёрнуто)

> Ведут прибыльное по сути ядро (пошив) и живой товарный контур, но управленчески смешивают их в одной картине и не видят себестоимость услуги — поэтому бизнес выглядит хуже и менее управляемым, чем есть по кассе.

Ниже — что это значит по слоям, почему так вышло, и **что делать по шагам**.

---

## 1. Что означает каждая часть тезиса

### 1.1. «Прибыльное по сути ядро (пошив)»

**Факты:**
- МД / Salon+Shop ≈ **83–84%** дохода 2025 (DDS ≈ **232.6M ₽** @EUR100).
- Платежи МД ↔ DDS сходятся хорошо (29/30 мес ≥2024).
- Банковский контур ИП живой; ядро реально генерирует входящий cash.

**Что из этого следует:**  
пошив — не «дотационный придаток», а **кормилец**. Любая оптимизация, которая бьёт по срокам/мощности ателье ради «минуса товара», бьёт по компании.

**Чего мы НЕ доказали:**  
что каждый заказ прибылен по contribution. Касса ≠ маржа заказа. Ядро «прибыльно по сути» = **кормит систему и сходится по деньгам**, не = «знаем GM пошива».

### 1.2. «Живой товарный контур»

**Факты:**
- IM: высокая GM (~80%+), канал экономически здоровый по валу.
- ЦУМ: большой объём; **product** GM ~88%, **reported** ~38% (комиссия в COGS Excel).
- B2B wholesale сжался, но ещё есть; open settle ~**2.51M**.

**Что из этого следует:**  
товар не мёртвый. Его нельзя вести тем же KPI, что пошив, и нельзя судить ЦУМ по одной цифре 38%.

### 1.3. «Управленчески смешивают в одной картине»

**Как это выглядит на практике:**
- В один «результат» попадают: выручка товара + почти весь ФОТ/аренда/opex, а **МД-выручка выпадает** → operating −58/−74%.
- В брифе «B2B» часто = ЦУМ; в учёте B2B wholesale и ЦУМ — разное.
- Решения («режем канал / режем ФОТ / всё убыточно») принимаются по смешанной картинке.

**Последствие:**  
бизнес **выглядит** хуже реальности. Страх и сокращения бьют не туда.

### 1.4. «Не видят себестоимость услуги»

**Факты:**
- В МД workbook за 2024–25 поля cost по заказам фактически пустые.
- Нет WIP/остатков МД, фурнитура вне нормального учёта.
- Proxy contribution можно только **экспертно/пилотом**, не из текущего periметра.

**Последствие:**  
нельзя управлять ценой, скидкой, сроком, аутсорсом и загрузкой цеха через «маржу заказа». Управление пошивом идёт через **деньги на счёте и загрузку**, не через unit-econ.

### 1.5. «Выглядит хуже и менее управляемым, чем есть по кассе»

| По кассе / сверкам | По смешанной отчётности |
|--------------------|-------------------------|
| Ядро кормит | «Компания −74%» |
| IM маржинален | «Товар тянет на дно» |
| ЦУМ product сильный | «ЦУМ 38% — почти убыток» |
| ЗП/opex суммами бьются | «Непонятно, куда деваются деньги» |
| Gate честно красит дыры | Ощущение хаоса без приоритизации |

Касса говорит: **система жива**.  
Смешанный отчёт говорит: **система в катастрофе**.  
Правда ближе к первому, с оговоркой: экономика заказа и часть канальной кассы недоуправляемы.

---

## 2. Почему так ведут (корневые причины)

1. **Исторически один Excel-мир** на разные экономики (услуга vs товар vs агент).  
2. **Нет правила чтения** (политики двух контуров / dual TSUM) как обязательного стандарта.  
3. **Учёт пошива не заточен под себестоимость** — заточен под заказ/оплату.  
4. **Контроль сильнее по суммам, слабее по закрытию месяца каналов** (IM, settle).  
5. **Рост сложности** (3 LE, ЦУМ, IM, ткани) без обновления модели управления.

Это не «плохой бизнес», это **устаревшая система координат**.

---

## 3. Что делать в данном случае (план)

Принцип: **сначала починить картину и дисциплину, потом рост, потом условия/затраты.**  
Не начинать с массового cut ФОТ и не резать ЦУМ по 38%.

```text
Неделя 0–2   →  Правила чтения + решения собственника
Месяц 1      →  S1 дисциплина кассы (то, что измеримо)
Квартал 1–2  →  S2 процессный рост МД (без фальшивой unit-маржи)
Далее        →  S3 только там, где есть рычаг без новых «магических» файлов
S4           →  не запускать без фактов (фактов unit/%% может не быть → S4 закрыт)
```

---

### Шаг A. Зафиксировать правила чтения (обязательно, сразу)

**Зачем:** перестать принимать решения по ложной картине.

| Действие | Кто | Результат |
|----------|-----|-----------|
| Утвердить **два контура** в любом отчёте (A пошив / B товар) | Янина + Сливяк/Мамушкина | Исчезает «один минус на всё» |
| Запретить goods operating % как KPI компании | Янина | Защита ядра от ложных cuts |
| ЦУМ всегда **dual**: reported + product | Сливяк / коммерция | Не режем канал по 38% |
| Decor не в operating KPI 2026+ | Янина | Чище periметр |
| Подписать черновики политик `08_POLICY_DRAFTS` | Owners | Этап 1 → управленческий стандарт |

Без шага A любой «оптимизационный» план опасен.

---

### Шаг B. S1 — дисциплина (30–60 дней)

**Зачем:** вернуть управляемость кассы и доверие к месяцу.

| # | Действие | Зачем | Ориентир эффекта |
|---|----------|-------|------------------|
| B1 | Закрыть B2B open (15 док / до 2.51M): статус collect/offset/bad debt | Убрать видимую утечку | до **1–2.5M** разово (не гарантия 100%) |
| B2 | Разобрать 6 IM OPEN + 5 BANK_DDS fails по тикетам gate | Месяц можно «отдавать» | качество; меньше BLOCKED |
| B3 | Не клеить POS 62M слепо в IM; завести правило класса POS (даже без нового файла — политика) | Не сломать recon | риск↓ |
| B4 | DDS SLA: июнь и дальше без «лага источника» | Ядро остаётся читаемым | процесс |
| B5 | Стоп wholesale below-cost без ACCEPT | Не копить ложную маржу | мелко, но дисциплина |

**Критерий успеха S1:**  
политики подписаны + B2B в работе + BLOCKED месяцев меньше + никто не принимает решений по −74%/TSUM 38% без dual.

---

### Шаг C. Управлять пошивом без unit-econ (раз документов не будет)

Раз себестоимости заказа в periметре нет — **не притворяемся, что она есть**.  
Управляем ядром через **операционные рычаги**:

| Рычаг | Что делать | Метрика (без COGS) |
|-------|------------|-------------------|
| Деньги заказа | Дисциплина предоплаты / этапов оплаты | % заказов с предоплатой; лаг оплаты |
| Цикл | Срок от заказа до сдачи / число переносов | cycle time; redo |
| Повтор | Допродажи и повторные клиенты | share повторных |
| Мощность | Не резать критичный ФОТ ателье «по товару» | загрузка / очередь |
| Касса ядра | МД payments ↔ DDS ежемесячно | CLOSE/SOFT как сейчас |

**Пилот (если когда-нибудь появится экспертная оценка, не файл):**  
10–20 заказов вручную (материалы/подряд/часы) → proxy contribution.  
Пока пилота нет — S2 только на метриках выше, не на «+маржа МД из Excel».

Ориентир S2 при удачном процессном росте МД +5–10%: **~5–12M ₽/год** — **гипотеза**, не обещание.

---

### Шаг D. Товарный контур — вести отдельно

| Канал | Делать | Не делать |
|-------|--------|-----------|
| **IM** | Растить после закрытия эквайринг-дыр; держать GM | Масштабировать при OPEN gate |
| **ЦУМ** | Смотреть product GM + комиссию отдельно; переговоры %% если появятся | Резать объём по reported 38% |
| **B2B** | Collect + запрет below-cost; объём не главный рычаг роста | Ждать, что опт «спасёт» компанию |

---

### Шаг E. Затраты и капитал — осторожно

| Тема | Что можно без новых документов | Чего нельзя |
|------|--------------------------------|-------------|
| ФОТ (+93% YoY в class) | Разбор статей/ролей на уровне, который есть; защита МД-критичных | Слепой cut −10–15% |
| Аренда | Пересмотр загрузки/условий | Ломать салон ради «экономии» без расчёта |
| Ткани ~28.6M | Инвентаризация/очевидный неликвид экспертно | Заявить точный ABC-SoT |
| Карта / прочий opex | Политика лимитов | Думать, что это спасёт ядро |

S3 «условия + видимость затрат» (ориентир 10–16M/год) — только после S1 и понимания, что режем **shared/товар**, не пошив.  
S4 структурный — **не рекомендован** при отсутствии unit МД и %% ЦУМ.

## 4. Роли: кто что делает

| Роль | Фокус |
|------|--------|
| **Янина** | Утвердить политики A/B, dual, запрет ложного KPI; go/no-go на cuts |
| **Сливяк** | Gate, bank/DDS/IM, tax cash, классы кассы, ЗП-суммы |
| **Мамушкина** | Касса МД / DDS / дисциплина оплат заказов |
| **Коптева** | B2B open + прайс-дисциплина |
| **Мокеева / Коновалова** | Если будет пилот proxy cost — производство/продукт; иначе не ждать файл |
| **Меркушина** | %% ЦУМ — если появится; иначе dual без ставки |

---

## 5. Чего не делать (анти-план)

1. Не строить стратегию от goods **−74%**.  
2. Не сокращать ЦУМ из‑за **38%**.  
3. Не резать ФОТ ателье, «потому что товар в минусе».  
4. Не ждать «ещё один Excel», чтобы закрыть Этап 1 — он уже закрываем.  
5. Не обещать заказчику/себе точную маржу пошива.  
6. Не запускать S4 «для красивой экономии».

## 6. Картина «как должно стать» через 90 дней

| Было | Стало |
|------|-------|
| Один страшный минус | Два контура в каждом отчёте |
| ЦУМ «плохой» | ЦУМ dual; объём под защитой |
| Месяц иногда нельзя читать | Меньше BLOCKED; тикеты по fails |
| B2B висит | Open в статусах / частично собран |
| Пошив «чёрный ящик» по марже | Пошив управляется циклом/оплатой/кассой |
| Решения из страха | Решения из кассы ядра + GM каналов |

Это и есть ответ «что делать в данном случае»:  
**сменить систему координат, закрыть измеримые дыры, растить ядро процессом, товар вести отдельно, costs — только после защиты пошива.**

## 7. Одна страница для собственника

1. Пошив — кормилец; товар — второй контур.  
2. Смешанный отчёт врёт; его меняем политикой.  
3. Себестоимость услуги сейчас не видим — и не будем, пока нет учёта заказа; управляем иначе.  
4. Ближайшие деньги/качество: B2B + gate + запрет ложных KPI.  
5. Рост: процесс МД и аккуратный IM.  
6. Жёсткие cuts — только если защитили ядро и поняли канал ЦУМ по dual.
