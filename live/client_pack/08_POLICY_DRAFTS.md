# 08 — Черновики политик / мини-регламентов

Updated: 2026-07-27

## P-A. Политика двух контуров отчётности

1. Любой управленческий отчёт по выручке/марже/результату помечает контур:  
   **A — МД/инд. пошив** или **B — товар (IM/B2B/TSUM)** или **A+B раздельно**.  
2. Запрещено публиковать goods operating result (−%/−₽) как результат компании YANINA.  
3. Смешанный «итог группы» допускается только после утверждённой Phase C политики (сейчас нет).  
**Approver:** Янина Ю.Ф. · **Owner данных:** Сливяк

---

## P-B. Политика отчётности ЦУМ (dual view)

1. По ЦУМ всегда два показателя: **GM reported** и **GM product** (пока не выбран режим C1/C2/C3).  
2. Запрещено принимать решение о сокращении/закрытии ЦУМ только по reported GM.  
3. Cash-сверка net-rate не вычитает комиссию повторно, если она уже в FILE COGS (до подтверждения Меркушиной).  
**Owner:** Коптева / Мокеева · **SME:** Меркушина

---

## P-C. DDS SLA (антилаг)

1. SALES DDS (Salon+Shop) обновляется не позднее **N рабочих дней** после конца месяца (рекомендация: 5).  
2. Если МД workbook уже содержит месяц, а DDS = 0 → статус **DDS_LAG**, эскалация Мамушкина/Сливяк.  
3. Gate не может быть «зелёным» по MD, пока DDS_LAG открыт.  
**Owner:** Сливяк · **Исполнение:** Мамушкина

---

## P-D. Release Gate (операционный)

1. Месяц **RELEASED**, если все gate-controls в CLOSE/SOFT.  
2. BLOCKED ≠ «закрыт учёт»; = «нельзя опираться на месяц без оговорки».  
3. Политика PROVISIONAL, пока не назначен data steward и не закрыты P0 кассовые дыры.  
**Owner:** Сливяк

---

## P-E. B2B settle

1. Каждая open-накладная имеет статус: оплачено / взаимозачёт / нет в выписке / ошибка документа.  
2. Срок разбора open > 30 дней — эскалация Коптева → Янина.  
**Owner:** Коптева

---

## P-F. Wholesale below cost

1. Новые продажи ниже себестоимости (FILE/W3) требуют письменного ACCEPT коммерции.  
2. Иначе строка в quarantine / исключение из clean margin.  
**Owner:** Коптева / Коновалова
