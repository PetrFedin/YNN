## 0. Как пользоваться

Для каждой группы три колонки смысла:

| Колонка | Значение |
|---------|----------|
| **Лежит** | Какие файлы / типы |
| **Уже посчитано** | Что сделано в анализе (есть цифры/сверки) |
| **Досчитать / нельзя** | Что ещё можно выжать из тех же файлов **или** чего не будет без новых данных |

В конце — **единая карта структуры данных** и **выводы**.

# Часть B. Единая карта / структура данных

Так сшивается всё в одну систему (уже построено как L0→L5):

```text
ГРУППЫ ДОКУМЕНТОВ                    РЕГИСТРЫ                    MARTS / ВЫВОДЫ
─────────────────────────────────    ─────────────────────       ─────────────────────────
A1 Банк + карта + Сбер        →      BANK                        касса, классы, Salon OK
A2 ДДС / расходы / SALES свод →      CASH, EXP, BUD              МД 232.6M, mix, bridge−74%
A3 Продажи IM/B2B/ЦУМ         →      SALES, SETTLE               GM каналов, dual, open 2.51M
A4 Cost + МД workbook         →      COST, (MD extracts)         товарный COGS; пошив БЕЗ unit
A5 Номенклатура/коллекции     →      SKU                         top SKU; коллекции — запас
A6 Ткани/склады/закупки       →      MAT, SUP                    ткани ~28.6M; фурнитуры нет
A7 ЗП                         →      PAYROLL, EMP                суммы OK; lines дыры
A8 Налоги PDF                 →      TAX                         cash OK; PDF amounts partial
A9 Договоры/RACI              →      LEGAL / governance          owners, границы этапа
                                      ↓
                               CONTROLS + GATE (18/30)
                                      ↓
                               CLIENT PACK (диагноз, сценарии, план)
```

### Ключи связи (как склеивать)

| Связь | Ключ |
|-------|------|
| Банк ↔ ДДС | месяц + сумма + статья/контрагент |
| МД payments ↔ DDS | месяц + EUR/канал |
| Sales ↔ Cost | SKU / артикул |
| Sales ↔ Bank (IM) | месяц + эквайринг-класс |
| B2B ↔ Bank | документ + сумма + контрагент |
| ЗП ↔ Bank/DDS | месяц + суммы |
| Налоги ↔ Bank | платежи УФК/ФНС |

### Два контура на карте (обязательно)

```text
                    ┌─────────────── ОБЩИЕ ЗАТРАТЫ (ФОТ/аренда/…) ───────────────┐
                    │                         shared                              │
                    └───────────────┬─────────────────────────────┬───────────────┘
                                    │                             │
              КОНТУР A ПОШИВ        │                             │        КОНТУР B ТОВАР
         банк+DDS+МД payments       │                             │     sales+cost+settle
         НЕТ unit cost заказа       │                             │     ЕСТЬ GM по каналам
                                    ▼                             ▼
                         не смешивать в один «−74% KPI»
```

# Часть C. Что уже «сведено» vs что ещё «досчитать»

## Имеет смысл досчитывать **из уже лежащих файлов** (без новых документов)

## Не досчитывается из текущего periметра (принять как пробел)
- Unit-econ пошива  
- Фурнитура  
- % комиссии ЦУМ из договора  
- 100% IM CLOSE без реестров  
- Audited единый P&L

# Часть D. Выводы (после разбора всех групп)

1. **Документов достаточно для диагностики ведения бизнеса**, недостаточно для полной unit-экономики пошива и audited P&L.  

2. **Центр тяжести данных** — банк + ДДС + МД payments + продажи товара + cost товара.  

3. **Главный разрыв** — группа «себестоимость/МД»: касса пошива сильная, себестоимость услуги пустая.  

4. **Главная управленческая ошибка, видимая из данных** — чтение товарного bridge (−74%) как правды о компании при выпавшем ядре дохода.  

5. **Главные операционные дыры, видимые из данных** — B2B open 2.51M, IM/bank gate fails, рост ФОТ без person-lines, ткани без ABC.  

6. **Единая карта уже есть** (L0→L5 + этот разбор по группам); дальше не «собрать карту с нуля», а **пользоваться ею**: два контура, отдельные KPI, закрытие измеримых дыр.  

7. **Следующий шаг** — не новый поиск документов, а решения: политики чтения + S1 дисциплина + процессное управление пошивом без фальшивой маржи заказа.
