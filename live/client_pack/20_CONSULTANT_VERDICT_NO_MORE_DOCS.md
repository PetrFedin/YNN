## 1. Короткий вердикт

**Этап 1 как комплексная диагностика — можно и нужно закрывать.**  
На имеющихся данных картина бизнеса **достаточна для управленческих решений о направлении**, но **недостаточна для единого audited P&L и для «точной» маржи индивидуального пошива**.

Если документов больше не будет, честная позиция консультанта такая:

1. **Не обещать** unit-econ МД, полный налоговый разбор PDF, ABC тканей «как факт», collectability B2B 100%, договорной % ЦУМ.  
2. **Отдать** полный диагностический пакет Этапа 1 с жёсткими оговорками и сценариями.  
3. **Считать «дыры» постоянными ограничениями модели**, а не «ещё чуть-чуть доработаем Excel».  
4. Дальше ценность только в **решениях owners и изменении процессов/отчётности**, не в ожидании новых файлов.

## 2. Что данные позволяют утверждать уверенно

Это то, с чем можно выходить к собственнику без стыда и без дорисовок.

### 2.1. Модель бизнеса
- Бизнес **двуконтурный**: ядро — **МД / инд. пошив** (~84% дохода 2025 по DDS), второй контур — **товар** (IM / B2B / ЦУМ).  
- Смешение контуров в одном «P&L/operating %» **искажает решения**. Goods operating **−74% (2025)** / **−58% (30 мес.)** — артефакт periметра (МД вне выручки при почти полном opex), **не** доказанный убыток компании.

### 2.2. Деньги и качество кассы
- Банк periметр измерим (**4933** платежа); Salon Sber свежие выписки **сходятся 510/510**.  
- МД payments ↔ DDS ≥2024: **высокая** согласованность (29/30; лаг июня 2026 — дыра источника periметра, не «нет МД»).  
- Payroll / opex multi-controls по суммам — **сильные**.  
- Tax cash в банке — **высокий** %.  
- При этом **качество месяца** неравномерно: gate **18 RELEASED / 12 BLOCKED** (IM, bank↔DDS, точечно TSUM/tax).

### 2.3. Товарный контур
- IM держит **высокую** GM (~80%+).  
- B2B wholesale **сжался** и даёт open settle **~2.51M** — это конкретная кассовая утечка, не теория.  
- ЦУМ: reported GM **~38%** и product GM **~88%** — два разных мира; комиссия в Excel COGS (~**61M / 30 мес** proxy) делает «оптимизацию ЦУМ по 38%» опасной ошибкой.

### 2.4. Управление
- RACI / owners **названы** (staging domain-owned).  
- Есть дисциплина gate, freeze, запреты SoT — это уже продукт Этапа 1, не «сырые файлы».

**Итог уверенности:** касса ядра + товарная маржа + ловушки отчётности — **доказаны достаточно**, чтобы менять правила управления.

## 3. Что данные НЕ позволяют утверждать (и уже не позволят)

При «документов больше не будет» эти пункты становятся **постоянными белыми пятнами** в модели. Их нельзя «дожать анализом».

| Белое пятно | Почему навсегда (без новых файлов) | Как говорить заказчику |
|-------------|------------------------------------|------------------------|
| Маржа / contribution заказа МД | В workbook cost за 2024–25 фактически пуст; price ≠ DDS | «Ядро видим по кассе, не по марже заказа» |
| Остатки / WIP МД | Нет в periметре учёта | «Неуправляемый склад услуги» |
| Фурнитура | Невидима в 1С, только намёки в ДДС | «WC неполный» |
| Договорной % ЦУМ | Нет договора/ответа в файлах | «Dual view — метод; ставка — неизвестна» |
| 100% закрытие IM OPEN | Нет реестров на часть месяцев; POS≠IM влоб | «Часть месяцев читаем с оговоркой» |
| Collectability B2B | Есть список долга, нет актов/оплат | «Потолок 2.51M; факт сбора неизвестен» |
| Person-level ФОТ / split МД vs товар | Multi CLOSE, lines дырявые | «ФОТ бьётся суммой, не людьми» |
| Полные суммы налоговых PDF | Extract неполный | «Налоги видим в кассе, не во всех декларациях» |
| ABC неликвида тканей | Есть ~28.6M end, нет aging-аналитики как SoT | «Капитал виден порядком, не ABC» |
| Единый audited P&L | Методологически нельзя из staging | «Две экономики + касса, не одна прибыль» |

**Консультантская этика:** лучше зафиксировать эти ограничения в договоре/акте Этапа 1, чем имитировать полноту.

## 5. Мой вывод по существу бизнеса (на том, что есть)

### 5.1. Где правда о деньгах
Правда сейчас живёт в **кассе и сверках**, не в «марже всего бизнеса».  
Ядро (МД) нужно вести как **cash + заказная дисциплина**; товар — как **GM по каналам с dual для ЦУМ**.

### 5.2. Где главный риск ошибок
1. Резать/паниковать по goods **−74%**.  
2. Резать ЦУМ по **38%**.  
3. Ждать «ещё Excel» вместо смены правил отчётности.  
4. Называть staging **аудированной** прибылью.

### 5.3. Где реальные рычаги без новых документов
Именно процессы и решения, не данные:

| Рычаг | Тип | Ориентир | Условие честности |
|-------|-----|----------|-------------------|
| Разделить отчётность A/B + dual TSUM | Управление | риск↓ (критично) | ACCEPT политик |
| B2B open collect | Cash | до **2.51M** разово | не гарантировать 100% |
| Дисциплина gate / DDS / эквайринг | Качество | меньше BLOCKED | без реестров — потолок |
| Не трогать ЦУМ объём до C-режима | Защита дохода | сохранить product-экономику | dual всегда рядом |
| Сценарий роста МД (S2) | Рост | **5–12M/год** | **гипотеза**; без cost — только процессные KPI |
| S3 условия/затраты | Условия | **10–16M/год** | без % ЦУМ и split ФОТ — слабее |
| S4 структура | Cut | 15–25 / стресс 5–10 | **не запускать** без фактов; фактов не будет → S4 по сути закрыт |

**Важный вывод при «файлов не будет»:**  
траектория **S1 (обязательно) → осторожный S2 на процессных метриках → урезанный S3** (то, что не требует договора ЦУМ и person-ФОТ).  
Полноценные S3/S4 **нечестны** как «точные» — их можно оставить как стресс-вилки, не как план.

### 5.4. Прибыльность «в целом»
На текущих данных **нельзя честно сказать «компания прибыльна/убыточна на X%»**.  
Можно сказать:
- ядро **кормит кассу** и сходится с DDS;  
- товар **маржинален по GM**, но не тянет весь opex один;  
- отчётность делала вид, что «всё в минусе»;  
- исправление модели чтения + кассовая дисциплина + рост/дисциплина ядра — путь к управляемой прибыльности, а не один cost-cut.
