## 3. Причинно-следственная цепочка проблем

```
Нет unit МД (P01)
  → нельзя оптимизировать 83% бизнеса по марже
  → S2-сценарии остаются гипотезами

IM без эквайринг-реестров (P02)
  → 6 OPEN → месяцы BLOCKED
  → нельзя закрывать periметр товара по кассе

BANK↔DDS WIDE_GAP (P11)
  → 5 fail → BLOCKED + недоверие к кассе
  → мешает S1 «дисциплина»

TSUM commission в COGS (P03)
  → reported 38% выглядит «плохо»
  → риск закрыть/урезать канал с product GM ~88%

B2B open 2.51M (P04)
  → прямой CF drag
  → быстрый one-time в S1

Ткани 28.6M без ABC (P05) + фурнитура невидима (P06)
  → капитал заморожен / WC слепой
  → S3 prep

Goods bridge как «P&L» (P12)
  → ложные стратегические решения
  → governance P0
```

## 6. Единый алгоритм углублённого чтения (практика)

1. Вопрос → процесс P0x (`01`)  
2. Факт только из RELEASED месяца или с пометкой BLOCKED (`05`)  
3. Число → регистр/mart (`03` + snapshot)  
4. Контур A/B и dual TSUM (`06`, `08`)  
5. Если решение меняет SoT → owner ACCEPT, иначе staging flag  
6. Сценарий ₽ только после S1 фактов (`OPTIMIZATION_SCENARIOS`)
